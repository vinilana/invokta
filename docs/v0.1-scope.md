# v0.1 scope and limits

## Public packages

**AE-SCOPE-01 — Three packages.** Version 0.1 contains only:

| Package | Responsibility |
| --- | --- |
| `@invokta/core` | Capability, Engine, Context, Principal, validation, access, errors, and events |
| `@invokta/cli` | `list`, `describe`, `run`, JSON through an argument/stdin, and rendering |
| `@invokta/mcp` | tools over stdio and stateless Streamable HTTP |

The packages are ESM. Apart from `@standard-schema/spec` when necessary, the core
has no runtime dependencies. The CLI and MCP depend only on the core's public API
to execute capabilities.

## What belongs to each layer

**AE-SCOPE-02 — Framework.** The framework provides typed definitions,
validation, registration in an engine, direct execution, minimal context, access
enforcement, events, and CLI/MCP adapters.

**AE-SCOPE-03 — Custom engine.** Capabilities, prompts, recipes, model/data
integrations, business rules, domain authorization, evals, metrics, and dependency
lifecycle belong to the engine built by the user.

**AE-SCOPE-04 — Evolution by extraction.** Ready-made auth, OpenTelemetry, evals,
model adapters, routing, cache, context compilation, scaffolding, and generators
may be introduced only after proven repetition across real engines.

## Explicit limits

| Dimension | v0.1 limit |
| --- | --- |
| Public packages | 3 |
| Official adapters | CLI and MCP |
| MCP transports | stdio and stateless Streamable HTTP |
| Core primitives | Capability, Engine, Context, Principal |
| Required capability fields | 5 |
| Pipeline stages | 6 |
| Error codes | 7 |
| Cross-cutting hooks | 1: `onEvent` |
| Auth/PDP implementations | 0 |
| Containers, modules, or plugins | 0 |

**AE-LIMIT-01 — Runtime.** The following are not included: universal lifecycle,
queue, concurrency, automatic retries, distributed execution, jobs, scheduler,
arbitrary streaming, and a progress API.

**AE-LIMIT-02 — Architecture.** The following are not included: formal modules,
port registry, dependency container, plugin loading, manifest compiler, and remote
registry.

**AE-LIMIT-03 — AI and quality.** The following are not included: model router,
context compiler, memory, RAG abstraction, prompt registry, official providers,
semantic cache, economics engine, eval runner, LLM-as-judge, release gates, and
canary.

**AE-LIMIT-04 — Security.** The following are not included: an auth package,
JWT/JWKS, universal introspection, DPoP, mTLS, an RBAC/ABAC language, a ReBAC
graph, a PDP adapter, session binding, and an Authorization Server.

**AE-LIMIT-05 — MCP.** The following are not included: resources, prompts,
sampling, elicitation, tasks, stateful sessions, resumption, and server-to-client
requests.

## Evolution triggers

An extension may be included only after evidence exists. Examples: OAuth
authentication after three engines repeat the integration; a PDP adapter after
two engines repeat the same vendor; modules when object spread fails to address
real ownership; lifecycle when several dependencies repeat start/stop; evals and
OpenTelemetry when two engines share the same need.
