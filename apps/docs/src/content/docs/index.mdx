## One capability, four entry points

An Invokta capability has typed input and output schemas, an explicit access rule,
and one handler. The engine publishes it through direct TypeScript calls, a local
CLI, MCP stdio, and stateless MCP Streamable HTTP.

  <Card title="Stable contracts" icon="seti:typescript">

## The smallest useful engine

```ts
import { createEngine, defineCapability } from "@invokta/core";
import { z } from "zod";

const greet = defineCapability({
  description: "Create a welcome message for a new team member.",
  input: z.object({ name: z.string().trim().min(1) }),
  output: z.object({ message: z.string() }),
  access: "public",
  async run({ input }) {
    return { message: `Welcome, ${input.name}!` };
  },
});

export const engine = createEngine({
  name: "hello-engine",
  version: "1.0.0",
  capabilities: {
    "onboarding.create-welcome-message": greet,
  },
});
```

The capability ID belongs to the engine map. The capability itself contains the
contract and implementation that every entry point reuses.
