An **Action Engine** is a versioned software component that publishes reusable,
AI-supported domain capabilities through stable contracts. Models, prompts, data,
retrieval, and tools remain replaceable implementation details.

Invokta is a framework for building Action Engines. It supplies the contracts,
runtime, and adapters. Your engine supplies the domain language and business
behavior.

## What qualifies as an Action Engine

An implementation qualifies when it:

1. publishes at least one domain-oriented operation;
2. validates its input and output at runtime;
3. hides the AI implementation behind that contract;
4. reuses the same operation through more than one execution channel; and
5. has a clear unit of ownership and versioning.

An operation such as `support.classify-ticket` describes a domain outcome. An
operation such as `llm.complete` exposes infrastructure and leaves every consumer
responsible for the business contract.

A product can contain all four responsibilities, but the Invokta core does not
couple them. That boundary keeps an engine usable from a test, a command, an MCP
client, or another application.

## Stable outside, replaceable inside

Suppose `support.classify-ticket` accepts a ticket ID and returns a queue,
priority, and explanation. Its implementation can move from one model provider
to another, add retrieval, or replace a prompt with deterministic rules. The
consumer continues to send and receive the same validated objects.

<Aside type="note" title="Version the contract deliberately">
  Changing a provider is usually internal. Removing an output field or changing
  the meaning of a capability ID changes what consumers rely on and requires a
  compatibility decision.
</Aside>
