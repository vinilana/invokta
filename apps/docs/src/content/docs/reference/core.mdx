`@invokta/core` contains the Action Engine contract and runtime. It defines the
optional connector authoring contract but has no CLI, MCP, HTTP, model SDK,
identity SDK, provider connector, or application framework dependency.

## Install

Install the core and a schema implementation compatible with both Standard
Schema v1 and Standard JSON Schema v1:

```sh
yarn add @invokta/core zod
```

Zod 4 is used by the examples, but it is not part of the core contract. The
package is native ESM and is verified on Node.js 22.20.0 or later. It imports no
Node.js built-in module and uses only ECMAScript and Web platform APIs, so it
also runs on Fetch runtimes such as Deno, Bun, and Cloudflare Workers by design.
On Node.js it requires `process.getBuiltinModule`, which Node.js 22.3 and
later provide, and refuses to load without it. On other hosts without it, proxy
recognition uses the portable fallback of ADR 0042.

## API

The package root exposes these public groups:

| Group | Exports |
| --- | --- |
| Capability | `defineCapability`, `CapabilityDefinition`, `AnyCapability`, `CapabilityMap`, `CapabilityAnnotations`, `CapabilityDeprecation`, `AccessRule`, `CapabilityAccessKind` |
| Connector | `defineConnector`, `ConnectorConfigSchema`, `ConnectorDefinition`, `ConnectorFactory`, `ConnectorInstance`, `ConnectorPorts`, `InferConnectorConfigInput`, `InferConnectorConfigOutput` |
| Engine | `createEngine`, `Engine`, `EngineDefinition`, `InvokeOptions`, `CapabilitySummary`, `CapabilityDescription` |
| Schema | `EngineSchema`, `EngineJsonSchema`, `InferSchemaInput`, `InferSchemaOutput` |
| Identity and context | `Principal`, `ExecutionContext`, `ExecutionSource`, `EngineLogger` |
| Events | `EngineEvent` |
| Invocation errors | `EngineError`, `EngineErrorCode`, `DomainErrorPublicDetails` |
| Domain errors | `CapabilityError`, `CapabilityErrorArguments`, `CapabilityErrorDeclaration`, `CapabilityErrorDescription`, `CapabilityErrorMap` |
| Composition values | `ExportedCapability`, `CapabilityLibrary`, `CapabilityImport`, `AnyCapabilityImport`, `ComposedCapabilities`, `CapabilitySource` |
| Composition functions | `defineExportedCapability`, `defineCapabilityLibrary`, `importCapability`, `importCapabilities`, `composeCapabilities`, `isComposedCapabilities` |

| Middleware | `applyMiddleware`, `CapabilityMiddleware`, `CapabilityMiddlewareArgs` |

Only the package root is exported. Internal schema, pipeline, and composition
helpers are not public subpaths.

## `defineCapability`

```ts
function defineCapability<
  InputSchema extends EngineSchema,
  OutputSchema extends EngineSchema,
>(
  definition: CapabilityDefinition<InputSchema, OutputSchema>,
): CapabilityDefinition<InputSchema, OutputSchema>;
```

`defineCapability` preserves schema inference and returns the supplied
definition. It does not register, validate, or execute the capability.

```ts
interface CapabilityDefinition<InputSchema, OutputSchema> {
  readonly title?: string;
  readonly description: string;
  readonly input: InputSchema;
  readonly output: OutputSchema;
  readonly access: AccessRule<InferSchemaOutput<InputSchema>>;
  readonly timeoutMs?: number;
  readonly annotations?: CapabilityAnnotations;
  readonly deprecated?: CapabilityDeprecation;
  readonly errors?: CapabilityErrorMap;
  readonly run: (args: {
    readonly input: InferSchemaOutput<InputSchema>;
    readonly context: ExecutionContext;
  }) => Promise<InferSchemaInput<OutputSchema>>;
}
```

The five required fields are `description`, `input`, `output`, `access`, and
`run`. `timeoutMs` must be an integer from `1` through `2_147_483_647`. With no
timeout, execution remains bounded only by caller cancellation and the
capability's own dependencies.

### Annotations

```ts
interface CapabilityAnnotations {
  readonly readOnly?: boolean;
  readonly destructive?: boolean;
  readonly idempotent?: boolean;
  readonly openWorld?: boolean;
}
```

Annotations are copied metadata and map to MCP tool hints. The core does not
enforce side effects, retries, rollback, idempotency, or network access from
these values.

### Domain errors

```ts
interface CapabilityErrorDeclaration {
  readonly description: string;
  readonly details?: EngineSchema;
  readonly retryable?: boolean;
}

type CapabilityErrorMap = Readonly<Record<string, CapabilityErrorDeclaration>>;

class CapabilityError<
  Errors extends CapabilityErrorMap = CapabilityErrorMap,
  Code extends Extract<keyof Errors, string> = Extract<keyof Errors, string>,
> extends Error {
  readonly code: Code;
  readonly details?: unknown;
  readonly cause?: unknown;
  constructor(...args: CapabilityErrorArguments<Errors, Code>);
}
```

`errors` declares the stable failure outcomes of a capability, keyed by an
UPPER_SNAKE_CASE domain code of at most 64 characters that differs from every
framework code. A capability declares at most 64. `description` is a non-empty
string of at most 1,024 characters and becomes the public message. `details` is
an optional object-rooted schema with Standard JSON Schema support, and
`retryable` defaults to `false`. `createEngine` validates and snapshots the map
and rejects proxies, accessors, and unknown fields with `TypeError`.

```ts
const errors = {
  TICKET_NOT_FOUND: {
    description: "The requested ticket does not exist.",
    details: z.object({ ticketId: z.string() }),
  },
} satisfies CapabilityErrorMap;

// Inside run:
throw new CapabilityError<typeof errors>("TICKET_NOT_FOUND", {
  details: { ticketId: input.ticketId },
});
```

`CapabilityError` is a standalone export because the execution context carries
no error factory. With the optional type argument, `CapabilityErrorArguments`
restricts the code to the declared keys and the details to the input type of the
matching schema; without it, any code and details compile. The engine checks
the raised error against the snapshotted declaration and publishes a
`DOMAIN_ERROR`, or fails closed with `EXECUTION_FAILED`. Only errors raised by
`run` and created by the constructor qualify; the engine uses the
constructor-time code and details. See [declared domain errors](/reference/errors/#declared-domain-errors).

The error must come from the same installed copy of `@invokta/core` as
`createEngine`. A capability package that resolves its own copy keeps its
declarations in `describe`, but its domain errors become `EXECUTION_FAILED`;
capability packages should declare the core as a peer dependency or be
deduplicated to one version. With the optional type arguments,
`CapabilityError<typeof errors>` types `code` as the union of declared codes and
`CapabilityError<typeof errors, "TICKET_NOT_FOUND">` as that one code; both stay
assignable to `CapabilityError`.

### Deprecation

```ts
interface CapabilityDeprecation {
  readonly reason: string;
  readonly since?: string;
  readonly replacement?: string;
}
```

```ts
const classifyTicket = defineCapability({
  description: "Classify a support ticket.",
  input,
  output,
  access: "authenticated",
  deprecated: {
    reason: "Superseded by the triage flow.",
    since: "2.0.0",
    replacement: "support.triage-ticket",
  },
  run,
});
```

`deprecated` marks a capability that consumers should stop using. `reason` is
required. `since` usually names the engine version that deprecated the
capability, and `replacement` usually names the capability to use instead; the
core does not check that it exists, because composition may remap IDs.

`createEngine` validates the notice synchronously. It must be a plain object of
enumerable data properties named `reason`, `since`, or `replacement`, and each
present value must be a non-blank string of at most 1,024, 64, and 256
characters respectively. An `undefined` optional value counts as absent.
Anything else, including accessors, proxies, and unknown fields, throws a
`TypeError` without running caller code.

Deprecation does not change invocation: the same pipeline, events, errors, and
results apply. The first time each deprecated capability is invoked in an
engine, after the capability is resolved and before input validation, the
engine logs one warning:

```ts
logger.warn("Deprecated capability invoked.", {
  capabilityId,
  requestId,
  since,       // when declared
  replacement, // when declared
});
```

A throwing or rejecting logger does not affect the invocation.

## `defineConnector`

```ts
function defineConnector<
  Name extends string,
  ConfigSchema extends ConnectorConfigSchema,
  Dependencies,
  Ports extends ConnectorPorts,
>(
  definition: ConnectorDefinition<
    Name,
    ConfigSchema,
    Dependencies,
    Ports
  >,
): ConnectorFactory<Name, ConfigSchema, Dependencies, Ports>;
```

`defineConnector` captures a connector definition without validating
configuration, invoking the connector factory, performing I/O, registering a
provider, or changing an engine. The returned factory has a literal `name` and a
synchronous `create(config, dependencies)` operation.

```ts
const firecrawl = defineConnector({
  name: 'firecrawl',
  config: z.object({
    apiKey: z.string().min(1),
    baseUrl: z.string().url().optional(),
  }),
  create(config, dependencies: { fetch: typeof globalThis.fetch }) {
    return {
      ports: {
        crawler: createFirecrawlWebCrawler({
          ...config,
          fetch: dependencies.fetch,
        }),
      },
    };
  },
});

const connector = firecrawl.create(
  { apiKey: environment.FIRECRAWL_API_KEY },
  { fetch: globalThis.fetch },
);

const engine = createCrawlEngine({
  crawler: connector.ports.crawler,
  permissions,
});
```

The configuration schema needs Standard Schema v1 validation but not Standard
JSON Schema. Validation must complete synchronously and transform to a lossless
JSON object. The core copies and freezes that validated object before the
connector callback runs. Opaque dependencies such as transports, SDK clients,
clocks, and pools are passed through by identity and are not configuration.

The callback returns at least one named port. The core shallow-copies and freezes
the connector instance and ports container while preserving port implementation
identity. The name, configuration, dependencies, and connector instance are not
published through `createEngine`, `ExecutionContext`, `list`, `describe`, CLI,
or MCP. Capabilities receive only the narrow ports they use.

Configuration validation failures throw a sanitized `TypeError` with
`Connector configuration is invalid.` Async validation throws
`Connector configuration validation must be synchronous.` Definition errors
reject an empty name, malformed schema, or missing factory before creation.
Creation rejects a missing ports record or an empty ports record. Exceptions
thrown by the connector callback after successful validation are preserved.

The helper does not provide discovery, automatic wiring, runtime lookup,
provider packages, retries, or lifecycle. Existing ordinary TypeScript connector
factories remain valid.

## Schema contract

```ts
interface EngineSchema<Input = unknown, Output = Input> {
  readonly "~standard":
    StandardSchemaV1.Props<Input, Output> &
    StandardJSONSchemaV1.Props<Input, Output>;
}

type InferSchemaInput<Schema extends EngineSchema> =
  StandardSchemaV1.InferInput<Schema>;

type InferSchemaOutput<Schema extends EngineSchema> =
  StandardSchemaV1.InferOutput<Schema>;

type EngineJsonSchema = Readonly<Record<string, unknown>>;
```

`invoke` accepts the input schema's input type. Validation may transform it;
`access` and `run` receive the transformed output type. The handler returns the
output schema's input type, and `invoke` resolves to its transformed output
type.

Both schemas must describe an object root. Their JSON Schema converters run
synchronously during `createEngine`; generated documents are copied and frozen.
Validated values must remain in Invokta's lossless JSON model: `null`, strings,
booleans, finite numbers other than negative zero, dense arrays, and ordinary
records containing the same values.

Values such as `undefined`, bigint, symbols, functions, non-finite numbers,
sparse arrays, accessors, proxies, custom prototypes, dynamic `toJSON` values,
and cycles fail as `INPUT_INVALID` or `OUTPUT_INVALID` without exposing the
rejected value.

## `createEngine`

```ts
interface EngineDefinition<Capabilities extends CapabilityMap> {
  readonly name: string;
  readonly version: string;
  readonly capabilities: Capabilities;
  readonly logger?: EngineLogger;
  readonly onEvent?: (
    event: EngineEvent,
  ) => void | Promise<void>;
}

function createEngine<Capabilities extends CapabilityMap>(
  definition: EngineDefinition<Capabilities>,
): Engine<Capabilities>;
```

Construction captures every capability's top-level contract once. It validates
timeouts, domain error declarations, deprecation notices, and JSON Schema
documents synchronously, and copies annotations, declarations, deprecation
notices, and schemas away from producer-owned
objects. Later mutation of the original map or
definition cannot alter the registered contract.

Engine names, versions, and capability IDs are caller-owned strings. The core
does not impose semantic-version parsing or a dotted-ID grammar; composition
descriptors apply their own non-empty metadata and ID checks.

### `engine.invoke`

```ts
invoke<CapabilityId extends keyof Capabilities>(
  capabilityId: CapabilityId,
  input: InferSchemaInput<Capabilities[CapabilityId]["input"]>,
  options?: InvokeOptions,
): Promise<
  InferSchemaOutput<Capabilities[CapabilityId]["output"]>
>;
```

```ts
interface InvokeOptions {
  readonly requestId?: string;
  readonly source?: ExecutionSource;
  readonly principal?: Principal | null;
  readonly signal?: AbortSignal;
}
```

`requestId` defaults to a generated UUID, `source` defaults to `direct`, and
`principal` defaults to `null`. `source` is one of `direct`, `cli`, `mcp-stdio`,
`mcp-http`, or `http`.

The optional signal must be a platform `AbortSignal`; structural substitutes
and proxies are rejected safely. Caller cancellation and a capability timeout
become `CANCELLED`. The timeout starts after authorization and covers handler
execution plus asynchronous output validation.

The pipeline validates input, snapshots it for the request, snapshots identity,
applies `access`, executes `run`, and validates output. Authorization and
execution receive independent input and principal snapshots.

### `engine.list`

```ts
list(): ReadonlyArray<CapabilitySummary>;
```

Returns fresh, deeply frozen summaries containing `id`, `description`, optional
`title`, optional annotations, and the optional `deprecated` notice.

### `engine.describe`

```ts
describe(capabilityId): CapabilityDescription;
```

Adds frozen `inputSchema`, `outputSchema`, optional `timeoutMs`, the access
kind, and optional `errors` to the summary. A missing ID throws
`CAPABILITY_NOT_FOUND`.

```ts
type CapabilityAccessKind = "public" | "authenticated" | "function";

interface CapabilityErrorDescription {
  readonly code: string;
  readonly description: string;
  readonly retryable: boolean;
  readonly detailsSchema?: EngineJsonSchema;
}
```

`access` is `function` for a function rule; the rule itself is never exposed.
`errors` lists the declared domain errors in declaration order and is omitted
when none is declared. `detailsSchema` is the output-side JSON Schema of the
declared details schema.

## Identity and access

```ts
interface Principal {
  readonly id: string;
  readonly attributes?: Readonly<Record<string, unknown>>;
}

type AccessRule<Input> =
  | "public"
  | "authenticated"
  | ((args: {
      readonly principal: Principal | null;
      readonly input: Input;
      readonly context: ExecutionContext;
      readonly capabilityId: string;
    }) => boolean | Promise<boolean>);
```

A non-null principal must be structured-cloneable, have a non-empty `id`, and
use a record for `attributes`. Invalid identity fails as `UNAUTHENTICATED`
before `access` or `run`.

Function access permits execution only on `true`. A denial with no principal is
`UNAUTHENTICATED`; a denial with a principal is `FORBIDDEN`. Identity comes from
the trusted invocation or adapter boundary, not capability input.

## Context, logging, and events

```ts
interface ExecutionContext {
  readonly requestId: string;
  readonly source: ExecutionSource;
  readonly principal: Principal | null;
  readonly signal: AbortSignal;
  readonly logger: EngineLogger;
}
```

`EngineLogger` contains `debug`, `info`, `warn`, and `error`; every method takes
a message plus optional read-only details. Context carries request state, not a
dependency registry. Inject repositories, providers, and model clients through
capability factories.

`EngineEvent` is a union of:

- `invocation.started`: request ID, capability ID, source, optional principal
  ID, and ISO start time;
- `invocation.completed`: request ID, capability ID, and duration; and
- `invocation.failed`: request ID, capability ID, duration, normalized error
  code, and, for `DOMAIN_ERROR`, the declared `domainCode`.

The runtime calls started and exactly one terminal event in pipeline order.
Event promises are observed but not awaited, and hook or diagnostic-logger
failures do not replace the invocation result. Events are best-effort and carry
no business payload or credential by default. Use
[`@invokta/otel`](/reference/otel/) to export them as OpenTelemetry spans and
metrics.

## Capability composition

```ts
defineExportedCapability({ source, defaultId, capability });
defineCapabilityLibrary({ name, version, capabilities });
importCapability(exported, { as });
importCapabilities(library, { include, remap });
composeCapabilities({ local, imports });
isComposedCapabilities(value);
```

These functions publish atomic capabilities or libraries and combine them under
effective engine IDs. Their generic return types are `ExportedCapability`,
`CapabilityLibrary`, `CapabilityImport`, and `ComposedCapabilities`; the
read-only `AnyCapabilityImport` type represents either import form.

Composition is eager and immutable. It adds no discovery, namespacing,
precedence, or plugin lifecycle. Read [Capability packages](/guides/capability-packages/)
for copy-ready signatures and all import variants.

### Composition diagnostics

Detected issues throw an immutable `CapabilityCompositionError`:

```ts
class CapabilityCompositionError extends TypeError {
  readonly code: "CAPABILITY_COMPOSITION_INVALID";
  readonly issues: readonly CapabilityCompositionIssue[];
}
```

| Issue | Meaning |
| --- | --- |
| `CAPABILITY_ID_COLLISION` | Several local, atomic, or library declarations claim one effective ID |
| `CAPABILITY_IMPORT_INVALID` | An atomic import received no exported-capability descriptor |
| `CAPABILITY_IMPORT_ID_NOT_FOUND` | A library selection or remap names an unknown default ID |
| `CAPABILITY_REMAP_NOT_SELECTED` | A remap key was excluded by `include` |

`CapabilityDeclarationProvenance` identifies a declaration as local, atomic, or
library with only IDs and declared source metadata. Malformed descriptors or API
arguments may throw plain `TypeError` before issue collection.

Use `isCapabilityCompositionError(error)` rather than `instanceof` when two
installed copies of the core may exist. It recognizes the stable code and issue
shape. Use `isComposedCapabilities(value)` to confirm a map retains composition
provenance.

## `applyMiddleware`

```ts
interface CapabilityMiddlewareArgs {
  readonly capabilityId: string;
  readonly input: unknown;
  readonly context: ExecutionContext;
  readonly next: () => Promise<unknown>;
}

type CapabilityMiddleware = (
  args: CapabilityMiddlewareArgs,
) => Promise<unknown>;

function applyMiddleware<Capabilities extends CapabilityMap>(
  capabilities: Capabilities,
  ...middleware: readonly CapabilityMiddleware[]
): Capabilities;
```

`applyMiddleware` returns a new frozen map with the same keys, in the same
order, and the same static type. Each capability is a frozen copy that replaces
only `run` with the middleware chain. It keeps by identity every own property,
enumerable or not, and the contract fields `title`, `description`, `input`,
`output`, `access`, `timeoutMs`, `annotations`, `errors`, `deprecated`, and
`run` even when they are inherited. Other inherited members of a class-based
capability, such as methods and lazy getters, are neither invoked nor copied.
The function is eager and synchronous: it
reads each field once, registers nothing, performs no I/O, and calls no
middleware, access rule, or handler. With no middleware it returns a frozen copy
holding the original capabilities.

```ts
const timing: CapabilityMiddleware = async ({ capabilityId, context, next }) => {
  const startedAt = performance.now();
  try {
    return await next();
  } finally {
    context.logger.debug("capability.timing", {
      capabilityId,
      durationMs: performance.now() - startedAt,
    });
  }
};

const capabilities = applyMiddleware(
  composeCapabilities({ local, imports }),
  timing,
);

const engine = createEngine({ name, version, capabilities });
```

The first listed middleware is outermost and `run` is innermost. Applying
middleware to an already wrapped map adds the new chain outside the earlier one.
Because the chain replaces `run`, the engine validates input and enforces
`access` before the first middleware, applies `timeoutMs` and caller
cancellation to the whole chain through `context.signal`, validates the
outermost result against the output schema, and normalizes a middleware error
exactly like a `run` error. A `CapabilityError` from `run` passes through the
chain unchanged, and one thrown by a middleware resolves against the same
`errors` declaration. Either is published as `DOMAIN_ERROR` only when its code
is declared.

| Argument | Value |
| --- | --- |
| `capabilityId` | The capability's key in the map passed to `applyMiddleware` |
| `input` | A deep-frozen snapshot of the validated input, taken on first read and shared by the invocation's middleware; `run` receives its own unmodified copy |
| `context` | The engine's frozen `ExecutionContext`, passed through unchanged; `context.principal` is the same object `run` receives and must not be mutated |
| `next` | Runs the rest of the chain and `run`, resolving to the unvalidated result |

`next()` accepts no replacement input or context. A middleware may call it at
most once while it is pending. A repeated call, including a re-entrant one from
the next layer, or a call after the middleware settled rejects with `TypeError`
without running the next layer, and becomes
`EXECUTION_FAILED` if it propagates. A call after the invocation signal aborted
rejects with the abort reason without running the next layer. A layer started
with `next()` always settles before the calling middleware's result is
returned. When the middleware did not await it, its outcome is ignored. No part
of the chain outlives the invocation.

Read `input` before calling `next()` when the value as validated matters: `run`
owns its copy and may change it before a later first read. Identity decisions
belong in `access`, not in middleware. A middleware that never reads `input`
adds no copy of the payload. A wrapped `run` called directly outside the engine
needs a platform `AbortSignal` in its context and accepts the same inputs as the
original until a middleware reads `input`. The snapshot is memoized per `run`
arguments object, so pass a fresh arguments object to each direct call.

When the source map is a composed map, the result keeps its composition
provenance and `isComposedCapabilities` returns `true`; a plain map never gains
it. Wrapped capabilities may also be passed to `composeCapabilities`,
`defineExportedCapability`, and `defineCapabilityLibrary`. Middleware applied
before composition observes the key at that point, such as a library default
ID, rather than the consumer's effective ID.

A non-object or proxy map, a non-function middleware, and a capability that is
not a non-proxy object with a `run` function throw `TypeError`. The core ships
no concrete middleware; the [middleware recipe](/recipes/capability-middleware/)
provides tested audit, rate-limit, and cache examples with their production
limits.

## Invocation errors

`EngineError` contains `code`, `message`, optional `publicDetails`, and optional
internal `cause`. A `DOMAIN_ERROR` has the declared description as its message
and `publicDetails` typed by `DomainErrorPublicDetails`:

```ts
interface DomainErrorPublicDetails {
  readonly code: string;
  readonly retryable: boolean;
  readonly details?: Readonly<Record<string, unknown>>;
}
```

See the complete [error taxonomy](/reference/errors/).

Construction `TypeError`s and `CapabilityCompositionError` happen before an
invocation and emit no invocation event. Invokta has no automatic retry or
rollback policy, and cancellation remains cooperative: downstream dependencies
must observe `context.signal`.

<Aside type="note" title="Intentional limits">
  The core has no queue, concurrency controller, service container, model
  router, lifecycle manager, cache, retry policy, or default timeout. Read
  [scope and limits](/concepts/scope-and-limits/) before adding engine-local
  behavior around the runtime.
</Aside>
